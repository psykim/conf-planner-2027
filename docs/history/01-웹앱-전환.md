# 01. 아티팩트 → 독립 웹앱 전환 (v1.0.0, 2026-09-06)

## 왜
"2027 학회 플래너"는 Claude Code 아티팩트로 운영 중이었는데, 사용자(개인 요금제)는
아티팩트를 특정 팀원에게 공유할 수 없고(이메일 초대는 Team/Enterprise 전용) Gmail 커넥터
선언 때문에 공개 링크도 차단됐다(2026-09-06 공식 문서·공유 다이얼로그로 확인). 사용자가
옵션 3(독립 웹앱 재구축)을 선택 — 팀 전원이 Claude 계정 없이 쓰는 웹서비스로 전환.

## 결정 (사용자 결재 2026-09-06)
1. **인증**: 매직링크 + `conf_allowed_emails` 화이트리스트 (공용 접근코드 안 대신)
2. **호스팅**: GitHub Pages (Vercel/Netlify 안 대신)
3. **주간 루틴**(trig_01EcF3VGcm2ZEoBWB6LG5btq, 월 09:00 KST): 당분간 아티팩트만 갱신,
   웹앱 data.js는 수동 반영. 안정화 후 재편.
4. **기존 아티팩트**: 병행 유지(루틴 대상 + 교수 개인용). 팀 입력은 웹앱으로 일원화.
5. **Supabase는 신규 프로젝트($10/월) 대신 기존 `planb4u-pipeline` 재사용** — 기존 public
   테이블 전부 RLS 활성 확인 후 결재. `conf_` 접두사로 격리.

## 만든 것
- DB: `conf_attendance`(conf_id pk) · `conf_members`(text id, snake_case 컬럼 ↔ 프론트
  camelCase는 어댑터가 매핑) · `conf_allowed_emails` + `conf_is_allowed()`(authenticated 전용) ·
  `conf_email_allowed(text)`(anon 허용, 로그인 전 사전 확인용 — true/false만).
  마이그레이션 `conf_planner_2027_init`. 타임스탬프는 아티팩트판 그대로 epoch ms(bigint).
- RLS: 팀 데이터는 화이트리스트 사용자만 전체 CRUD. 화이트리스트 테이블은 본인 행만 select.
  검증: anon 0행 · 화이트리스트 사용자 전체 접근 · 미등록 로그인 사용자 0행 (SQL 시뮬레이션).
- 실데이터 이관: 아티팩트 공유 DB read_db 백업 → attendance 6건(vascog going, 나머지 skip) ·
  members 1건(김기웅/vascog, 아티팩트 id 그대로 보존).
- 프론트: `conference-planner-2027.html`(1303줄)을 index.html/styles.css/data.js/app.js로 분리.
  `window.claude.db` 호출부만 storeAPI(같은 doc/collection/onSnapshot 형태)로 치환하고
  뒤를 supabase-js v2로 구현(쓰기 후 즉시 refetch + realtime 이벤트 시 refetch).
  Gmail 검색·자동완성, Gmail 항공권 가져오기, Claude 편명 조회는 **흔적 없이 제거**(v1 범위 제외).
  구 flightNo/flightTime 필드도 제거(실데이터 전부 null이라 흡수할 것 없음).
- 검증: 실제 매직링크(Gmail 수신 → 토큰 verifyOtp) 로그인 · 대시보드/모달 렌더 스크린샷 ·
  CRUD 왕복 · 실시간(서버 SQL 변경 → 4초 내 화면 반영) · 콘솔 오류 0.

## ★ 실사고 — realtime은 구독 전에 setAuth
채널 구독이 `joined`/`SUBSCRIBED`로 멀쩡한데 이벤트만 오지 않았다. publication·정책 다 정상.
원인: 로그인 직후 우리 콜백이 라이브러리의 토큰 전파보다 먼저 채널을 만들어 **anon 토큰으로
조인**했고, RLS 필터가 이벤트를 걸렀다(진단: 명시적 `setAuth` 후 만든 채널은 수신됨).
해법: `startApp`에서 구독 전 `await sb.realtime.setAuth(session.access_token)` — CLAUDE.md 절대 규칙.
